# Keithley 2400 4-Wire 측정·그래프 문제 분석 (2026-09-08)

## 사용자 증상 및 확인 범위

4-Wire 평가에서 전류가 새는 것 같고 그래프가 제대로 표시되지 않는다는 신고.
사용자는 아직 장비 전면 표시값과 프로그램을 비교하지 못한 상태다.
이번에는 소스, 공식 매뉴얼, 모의 통신, 격리된 브라우저로 확인했으며 실장비 출력을 켜지 않았다.
따라서 물리적 누설전류의 발생 여부나 배선 정상 여부를 확인한 결과가 아니다.

## 확인한 소프트웨어 문제와 수정

1. **2400 전용 CSS 전체 누락**: 현재 `index.css`에는 `k2400` 스타일이 없었다.
   실제 브라우저에서 캔버스가 폭 320px로 표시되어 축 여백 306px를 빼면 그래프 영역이 14px밖에 남지 않았다.
   기존 배포 폴더의 `index.css`에서 Keithley 2400 전용 블록 210줄만 복구했다.
   중앙 그래프·상태 카드·표·안전 모달·참고 계산·2열 레이아웃이 복구되었으며 다른 장비 스타일은 유지했다.

2. **측정 기능이 장비의 이전 상태에 의존**: 전압 인가 시 CURR만, 전류 인가 시 VOLT만 켜고 있었다.
   `SENS:FUNC`는 Concurrent 상태에서 기능을 추가하므로 이전 RES 기능도 남을 수 있었다.
   출력 OFF 확인 후 측정 기능을 비우고, Concurrent ON과 VOLT/CURR 실측을 명시한다.
   두 실측 기능과 RSEN 상태를 출력 시작 전에 조회·검증하고 NPLC도 두 항목에 적용한다.
   모의 재현: 설정 1 V, 실측 0.9 V/0.0008 A에서 기존 1,250 Ω → 수정 후 1,125 Ω.
   Source I에서도 설정 0.001 A 대신 실측 0.0008 A로 같은 1,125 Ω을 계산한다.

3. **이전 자동 출력 OFF·트리거 설정 잔존 가능성**: 매 READ?마다 출력이 꺼지거나 여러 레코드가 반환되는 설정을 고정하지 않았다.
   `SOUR:CLE:AUTO OFF`와 적용값 확인으로 샘플 사이의 연속 DC 출력을 유지하고 ARM/TRIG 즉시·1회 및 ASCII를 지정한다.
   프로그램의 명시적 정상 종료·중지·Compliance·오류 OUTPUT OFF는 유지한다.
   이것이 사용자 실장비에서 실제로 켜져 있었는지는 미확인이다.

4. **부정확한 그래프·파싱**: 빈 수신 필드를 0으로 바꾸거나 긴 응답의 앞 4개 필드만 사용하는 파싱을 거부하도록 수정했다.
   그래프는 무효값 구간을 선으로 연결하지 않으며 단일 유효점도 점으로 표시한다.
   null을 0으로 계산하지 않고 실제 전류의 부호·크기를 그대로 보존한다.
   `[2400 READ]` 원문 로그를 추가했고, Sense 전환 중 중복 조작을 막았다.

## 재현 및 검증

- `scripts/test_keithley_2400.mjs`: 기존 안전 한도/파싱/저장 모델 테스트와 빈 필드, 다중 레코드, 낮은 전류 부호, 그래프 결측 구간 테스트 통과.
- `scripts/test_keithley_2400_lifecycle.mjs`: RS-232/GPIB 모의 연결, 정지, Compliance, 연결 해제, 사이클과 양쪽 Source 모드 실측 회귀 테스트 통과. 이전 RES 제거, 실측 설정 불일치 시 출력 시작 차단 확인.
- `scripts/test_keithley_2400_graph.mjs`: 로컬 HTTP 서버에서 실제 통합 앱과 Edge로 렌더링. 수정 전 320px 폭 검증 실패를 재현했고 복구 후 중앙 폭, 단일점, 결측 구간, 3축 렌더링 통과. API는 모의 처리하여 실제 평가 파일을 읽거나 변경하지 않는다.
- 유지보수 `verify_project.py`: JavaScript 22개 문법과 동작 테스트 3개 통과. 이후 기존 `build/build_standalone.py:189`의 빈 `else:` 들여쓰기 오류로 전체 검사는 중단된다. 이번 작업에서 해당 빌드 파일을 수정하지 않았다.
- EXE 빌드·dist 동기화는 수행하지 않았다. 기존 EXE에는 이번 소스 수정이 아직 포함되지 않는다.

## 실장비에서 남은 확인

알려진 저항 부하로 같은 순간의 장비 전면 전압·전류, `[2400 READ]` 로그,
프로그램 전압·전류·저항을 비교해야 한다. 연결 방식, 인가 모드/값, Compliance,
NPLC, FORCE/SENSE 결선도 함께 기록한다. 4-Wire 설정 조회는 물리적 Sense 접촉까지 검증하지 않는다.
0에 가까운 전류에서 `V/I` 저항이 크게 흔들리는 현상과 케이블·지그 누설은 별도로 판단한다.

## 2026-09-08 현장 재확인

- Web Serial FTDI `USB::0x0403::0x6001::INSTR`, 9600 8-N-1에서 Model 2400 S/N 1162685를 식별했다.
- 연결 초기화에서 OUTPUT OFF 확인, ID 조회, 4-Wire Remote Sense 적용/조회, 오류 큐 확인까지 통과했다.
- 이후 페이지 새로고침으로 연결 세션이 해제됐고 다시 열 때 `Failed to open serial port`가 발생했다. COM4가 다른 브라우저 탭 또는 프로그램에 점유된 상태여서 1 V/10 mA 실제 인가 측정은 수행하지 않았다.
- 화면이 축소·누락돼 보인 원인은 `index.css`에서 2400 전용 CSS 블록이 사라진 것이었다. 이전 검증 배포본의 2400 범위 스타일만 복구하고 `index.html` CSS 캐시 키를 `20260908_k2400`으로 갱신했다. 격리 브라우저 그래프 회귀 테스트를 다시 통과했다.
- COM4 잔여 Web Serial/VISA 세션을 해제한 뒤 Chrome에서 ASRL4 VISA로 재연결했다. 9 V Source V, 1 A Current Compliance, 4-Wire, FAST 0.1 NPLC, 1초 간격, 60초 실제 평가를 수행했다.
- 60개 Raw 응답에서 전압은 8.999826~9.000060 V(평균 8.999933 V), 전류는 1.419546 mA에서 0.720768 mA로 감소(평균 0.820553 mA), 계산 저항은 6.340 kΩ에서 12.487 kΩ으로 증가(평균 11.055 kΩ)했다. Compliance/OVP/Overflow는 없었고 종료 후 OUTPUT OFF를 확인했다.
- 그래프의 전압 실선은 약 9 V로 평탄하고, 전류 파선은 감소하며, 저항 점선은 증가하는 Raw 응답과 일치했다. 따라서 이번 패턴은 그래프 계산 오류나 프로그램이 만든 누설전류가 아니라 장비가 실제 반환한 샘플 전류 변화다. 장비 전면 표시값과의 동일 시점 비교는 별도로 남는다.
- 측정 완료 후 설정 입력이 계속 비활성화되는 추가 버그를 발견했다. `safeOff()`가 `S.busy=true`인 동안 컨트롤을 갱신한 뒤 finally에서 busy만 false로 바꾸고 재갱신하지 않은 것이 원인이었다. finally 마지막에 `updateControlState()`를 추가했고 이번 평가 종료 후 설정 버튼이 다시 활성화됨을 실기로 확인했다.
- 장비 전면의 전류 단위와 맞추기 위해 프로그램 화면의 실시간 전류, 그래프 범례/Y축, 결과 표의 최대·평균 전류를 mA로 변환했다. 내부 Raw 데이터·통신값·저항/전력 계산·XLSX Raw Data는 A 단위를 유지한다. 저장된 60초 평가가 화면에서 마지막 0.7208 mA, 최대 1.4195 mA, 평균 0.8206 mA로 표시되고 그래프 축도 Current (mA)임을 브라우저에서 확인했다.
- mA 화면에서도 작은 값이 지수형으로 보이던 공통 숫자 포맷을 전류 전용 고정 소수 포맷으로 교체했다. 예: 1.509 nA는 `0.000001509 mA`, 0.287 nA는 `0.000000287 mA`, 60초 실측은 최대 `1.4195 mA`·평균 `0.820553 mA`로 표시한다. 실시간 카드와 그래프 전류 눈금도 같은 일반 소수 형식을 사용한다.
- 사용자 요청에 따라 mA 표시는 계측기 전면과 동일하게 소수점 5자리 고정으로 변경했다. 이번 60초 평가는 마지막 `0.72077 mA`, 최대 `1.41955 mA`, 평균 `0.82055 mA`로 표시한다. 매우 작은 값은 mA 5자리 미만이면 `0.00000 mA`로 표시되며 Raw/XLSX의 A 값은 보존된다.
