# IMASS SP-2100 Raw 데이터 실기 분석 — 2026-09-03

## 결론

- 실장비가 시험 중/시험 후 약 3.4~3.7 KB의 바이너리 블록을 전송하는 것은 확인했다.
- 따라서 원시 바이트 수집과 `.bin` 보존은 가능하다.
- 그러나 해당 블록은 ASCII 측정값도, 일반적인 8/16-bit ADC 배열도 아니다.
- 현재 확보된 정보만으로 힘(g)·시간(s) 데이터로 디코딩하면 전 구간 잡음이 되므로 실제 파형 그래프로 표시하면 안 된다.
- 제조사 IMASS DataLink/StatsLink/ExLink의 프로토콜 또는 동일 측정의 제조사 Raw/CSV 내보내기 파일이 확보되어야 변환식을 검증할 수 있다.
- 정상 디코딩 후에는 캔버스 드래그 구간 선택과 선택 구간의 평균·최소·최대 계산을 구현할 수 있다.

## 실장비 및 연결

- 장치: 사용자가 연결한 IMASS SP-2100
- 포트: `COM5`
- USB 어댑터: FTDI `VID:PID=0403:6001`, Serial `FTFRXDKZA`
- 데이터 비트/패리티/정지 비트: 8-N-1 기준
- 장비 설정·교정·영점 명령은 전송하지 않았다.
- 능동 확인에서는 현재 통합 프로그램과 동일한 읽기 명령 `R\r`만 사용했다.
- 수동 확인에서는 어떤 명령도 전송하지 않았다.

## 캡처 결과

| 조건 | 결과 |
|---|---|
| 57600 baud, `R\r` 100회/30초 | 0 byte |
| 38400 baud, `R\r` 단 1회/12초 | 3,502 byte 단일 블록 |
| 38400 baud, 수동 45초/실제 시험 | 3,719 byte + 61 byte + 3,462 byte |
| 9600 baud, 수동 30초/실제 시험 | 780 byte 깨진 데이터; 38400 대비 약 1/4 수량 |

실측 대상에서는 38400 baud가 유효한 전송 속도로 보인다. 기존 모듈의 SP-2100 57600 baud 고정값과 다르므로, 향후 코드 변경 시 장비별 baud 선택 또는 자동 검출이 필요하다.

## 바이너리 분석

- 3,502-byte 단일 블록:
  - 고비트 바이트 43.4%
  - 엔트로피 7.418 bits/byte
  - `"AVG"`, `"PEAK"`, `"POINTS"`, `"SCALE"`, `"OFFSET"`, `"SPEED"`, `"TRAVEL"` 없음
- 7,242-byte 수동 시험 캡처:
  - 시험 블록 3,719 byte 및 3,462 byte, 중간 요약 후보 61 byte
  - 고비트 바이트 45.5%
  - 엔트로피 7.601 bits/byte
  - 위 ASCII 라벨 모두 없음
- 8-bit/16-bit, LE/BE, signed/unsigned, 시작 offset 0~255 후보를 비교했다.
  - 최선 후보의 연속 샘플 상관도는 약 0.08~0.15에 불과했다.
  - 모든 후보가 실제 힘 곡선이 아닌 전 구간 랜덤 노이즈 형태였다.
- 단순 7-bit mask, XOR 0~255, bit reverse/rotate/nibble swap으로도 측정 라벨이 복원되지 않았다.

## 외부 자료 확인

IMASS 제품 자료에는 SP-2100이 PC 인터페이스와 DataLink를 제공하며 StatsLink/ExLink로 데이터를 처리한다고 명시돼 있다. 이는 Raw 데이터 취득 기능이 장비에 존재함을 뒷받침하지만, 공개 검색으로 패킷 변환 규칙이나 DataLink 설치 파일은 확보하지 못했다.

## 필요한 다음 자료

다음 중 하나가 있어야 실제 Raw 그래프를 구현할 수 있다.

1. IMASS DataLink/StatsLink/ExLink 설치 파일 또는 설치 CD
2. 제조사 통신 프로토콜/개발자 매뉴얼
3. 동일 시험 1건의 제조사 프로그램 Raw/CSV 내보내기와 동시에 캡처한 `.bin`
4. 장비 전면 표시 AVG/KP/시험시간과 동일 시점 Raw 캡처 여러 건

## 구현 예정 구조 — 디코딩 확보 후

1. 시험별 `{time[], force[]}` Raw 배열 저장
2. 실제 Raw 배열로 힘-시간 그래프 표시
3. 마우스 드래그로 시작/종료 구간 선택
4. 선택 구간의 시작·종료시간, 샘플 수, 평균, 최소, 최대 표시
5. 선택 구간 강조 및 선택 해제/전체 구간 복원
6. Raw CSV 내보내기와 측정 기록별 파형 재호출

초기 분석 당시에는 디코딩 불확실 상태이므로 위 기능을 소스에 추가하지 않는 것으로 결론냈다.

## ComLink III 설치 원본 정적 분석

- 사용자 바탕화면의 `imass` 폴더는 설치 완료 폴더가 아니라 InstallShield 3 형식의
  `ComLink Version 3.0.135` 설치 원본이다.
- 설치 프로그램을 실행하거나 DLL/OCX를 등록하지 않고, 공개 MIT 도구 `setup30`으로
  작업 폴더의 `build_tmp/imass_extracted`에만 압축을 풀었다.
- 추출된 공식 실행 파일은 `ComLink30.exe`이며 제품 설명은
  `COM Port Communication with IMASS SP-2000`이다.
- 공식 통신 설정 화면의 선택지는 `38400`, `19200`, `9600` baud이고,
  안내문은 `COM1 and 38400 are the defaults.`이다. 직렬 형식 문자열은 `,N,8,1`이다.
- 공식 저장 형식은 Report TXT, Tabulated CSV, Archive ACV 및
  `Tabulated + XY plot`이다. 따라서 ComLink가 저장한 CSV/ACV를 이용한 파일 기반
  파형 취득 경로도 가능성이 있다.
- 공식 수신 검증에는 `No Start Code`, `No End Code`, `Miscount`,
  `Data Points do not add up!`가 존재한다. 즉 단순 ADC 배열이 아니라 시작/종료 코드와
  개수 검증이 있는 전용 프레임이다.

## Antigravity 변경분 검토 결과

- `instruments/sp2100_logger.js`에 38400 baud 선택, 파형 그래프, 드래그 구간 통계가
  추가되어 있다.
- 그러나 서버 또는 ComLink 저장 파일을 읽는 `fetch`/파일 가져오기 경로는 구현되어
  있지 않다. 따라서 현재 코드는 “장비 파일 가져오기”를 수행하지 않는다.
- 추가된 `ESC 0`/`ESC 1` 프레이밍은 공식 실행 파일의 오류 문구만으로 추정한 것으로,
  실장비 캡처에서는 완전한 해당 쌍이 확인되지 않았다.
- 프레임을 찾지 못하면 임의의 비인쇄 블록 전체를 기존 휴리스틱 `decodeWave()`에
  전달한다. 실장비 캡처로 검증했을 때 이 경로는 잡음 곡선을 만들므로 실제 Raw
  그래프로 취급하면 안 된다.

## 재개 지점

1. Antigravity가 추가한 그래프/드래그 UI는 보존한다.
2. 검증되지 않은 SP-2100 바이너리 자동 디코딩·표시 경로는 차단한다.
3. 공식 ComLink의 `Tabulated + XY plot` CSV 또는 ACV 샘플을 확보해 형식을 비교한다.
4. 가능하면 동일 시험의 ComLink 내보내기 파일과 직렬 `.bin`을 동시에 확보하여
   시작/종료 코드, 헤더 9바이트, 포인트 개수와 힘 변환식을 확정한다.
5. 형식 확정 후 파일 가져오기 또는 직접 직렬 디코더를 구현하고, 실제 Raw 배열에만
   구간 평균·최소·최대 기능을 활성화한다.
